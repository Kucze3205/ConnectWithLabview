## Envelope and byte originals

The separately named version is `synthetic-attempt-evidence/1`; it does not increment either existing schema. `/contract` defines fields; `/fixture` is a positive data fixture; `/controls` contains mutations and saved expected decisions/accounting. Apply each control to a fresh copy of `/fixture`. Controls contain data only and are never executed as Python.

| Object | Identity and meaning |
| --- | --- |
| Plan | Exact pinned 0138 synthetic plan and manifest bytes; explicit same-case/same-pair comparison and per-arm repetition map. The new envelope references their hashes and the canonical settings hash. The plan remains separately readable in the pinned source and retained evidence bytes. |
| Slot | Existing `record_id` plus `case_id`, `pair_id`, `repetition_id`, `arm`; `slot_ref` names that planned record ID. All five fields must match. Repetition labels remain repetitions, independent of attempt ordering. |
| Attempt | Unique synthetic `attempt_id`, unique positive `attempt_order`, ascending in list order; gaps are allowed. Multiple attempts may reference one slot and remain separately retained. The slot record ID is a join, not a substitute for attempt identity. |
| Evidence | Exactly the 23 inherited kinds plus `attempt_event`; synthetic object URI, producer/version, UTC, attempt identity, content type, explicit presence and payload reference. Every entry has `verification: not_performed`. |
| Payload | Original bytes in canonical lowercase `hex`, decoded byte size and SHA256; `utf8` is an independently readable view, exactly decoded text or null when invalid. Every catalog object is checked, including retained unreferenced originals. |

All content types are `application/octet-stream`; no UTF-8 or JSON assumption is imposed on request/response/error originals. For any materialized fixture `f`, recover an original without this checker using `bytes.fromhex(f['payloads'][payload_ref]['hex'])`. Hash and length operate on those bytes, never a reserialized response or its text view. Binary examples include NUL and invalid UTF-8. Malformed JSON remains malformed. An absent response has `presence: absent` and null reference; a present zero-byte response points to a payload with empty hex/text, size 0 and SHA256 `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`. Requests and errors always have present payloads, which may contain zero bytes. Missing required evidence is a rejection, distinct from a declared absent response.

`transport_outcome` is succeeded/failed/interrupted/unsupported and must match the retained synthetic `attempt_event` bytes. That event also retains attempt order, UTC labels, truncation, exhausted budgets and an explicitly synthetic cache inventory; queue/tool time remains unavailable (null). Event UTC labels are synthetic identifiers, not measured provider timing; inherited raw timestamp/usage/storage/isolation objects remain explicit placeholders. Old record timing/counters remain unchanged inside attached legacy records. No real timing reconciliation, resource accounting or trusted receipts are supplied.

Response parsing is derived separately as absent, empty, invalid UTF-8, malformed JSON or parseable JSON. Parseable does not mean correct or legacy-compatible. `legacy_record` is either an unchanged-schema synthetic record or null. When present, selected legacy helpers must accept it and its exact request/response/error bytes, identities and outcome flags must join the retained evidence. An old record cannot be attached to conceal empty output or substitute another answer. Null does not prevent attempt retention. Unbound request bytes can be retained with `input_binding: not_bound`; a byte match describes local identity only, never model delivery.

Synthetic URIs resolve to embedded catalog objects for this rehearsal only. Producer/version and UTC metadata bind local objects to attempts; matching hashes and metadata do not establish provider identity, external object existence, restricted storage, verifier authority or isolation. These actual authorities are unavailable. The repository-only checker cannot revalidate session export identities; their recorded provenance is explicitly marked as session-derived.

## Accounting and controls

Inventories distinguish planned slots, referenced present slots, missing slots, all retained attempts, unplanned references, multiple-attempt slots, present/absent/missing-evidence responses, empty/binary/malformed/parseable responses, attached/legacy-valid records and failed/interrupted/unsupported/succeeded events. Invalid controls retain diagnostic counts. `present_slots` means referenced planned slots, not validated linkage; `legacy_valid_records` checks legacy representation and raw-byte joins, not authority or admission. Event outcomes and parsing counts derive from bytes, rather than declared parsing/outcome summaries. Checker output includes independently recomputed size/hash/round-trip observations for each attempt's request, response and errors.

A structurally complete **synthetic** comparison requires valid linkage, one attempt per planned opposite-arm slot, byte-matched requests and two legacy-valid complete records without failure, errors, truncation, exhaustion or failed tool calls. Multiple attempts leave selection unresolved and yield zero completion, including when both succeed. Missing, failed, interrupted or unsupported arms also yield zero. No retry, selection, favorable substitution, response reuse or stopping policy is authorized. The inherited explicit repetition mapping remains authoritative; equality of cross-arm repetition strings is not a general rule. The unchanged 0138 checker additionally exercises declared arm-specific mappings.

Correctness and grounding independently retain D1–D4 and denominator **4** each. No submitted-claim denominator, semantic score or fidelity pass is invented. All actual admissions, model/reader/native executions, scored runs, semantic passes and real complete comparisons remain **zero**; actual provider/infrastructure/probe costs are **null**, and `benchmark_ready=false`. The unconditional real-admission block is a scope boundary, not a verified admission algorithm.
