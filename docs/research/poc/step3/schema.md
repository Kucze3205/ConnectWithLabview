# Edit-readiness evidence schema, version 1

The stdlib verifier implements this schema and referential checks; no network JSON Schema resolver is used. All evidence paths are relative to `docs/research/poc/`, must stay within that directory and must appear in the hash inventory. SHA256 values are 64 lowercase hex characters.

- `schema_version`: integer 1; `verdict`: `ready|partial|unsupported`; `summary`: nonempty string.
- `scope`: object recording `fixture_limit` (12), `edited_vi` and `behavior_claim` (both false), `save_version_policy`, and `runtime_checks` (nonempty owner-check list).
- `sources`: references to both provenance files and the source-search result. Provenance entries pin URL, local snapshot, size/hash; copied pylavi entries additionally pin revision, original path and license. Prepared-only source-search records retain original hashes but cannot be rehashed offline unless a matching snapshot is saved.
- `fixtures`: reference to the bounded fixture probe, including selection criteria, original paths, source families, original artifact hashes, parse results/failures and heap hashes where available. Original VI hashes are recorded provenance, not independently reverified when originals are absent.
- `evidence`: nonempty list of unique `{path, sha256, bytes}` records for small local evidence. JSON, text and script files are data; the verifier executes only the existing local inspector via import.
- `requirements`: exactly `semantics`, `connectivity`, `encoding`, `container_rebuild`, `integrity`, `compiled_cache`, `save_version`, `owner_runtime`; each has `status` (`resolved|unresolved|owner_check`), a concrete `finding`, and local `evidence` references.
- `blockers`: nonempty exact missing requirements for partial/unsupported; empty for ready. `exits`: at least two concrete alternatives for partial/unsupported.
- `spans`: original heap-body observations `{fixture, start, end, hex, field}`; half-open offsets include the heap length prefix. The two saved original compressed heaps are decompressed, hash-checked, parsed and compared to these spans. Saved constant entries and ancestor metadata are cross-checked against that parse.
- `recipe`: null for this partial result. Ready requires a recipe object with nonempty `before_meaning`, `after_meaning`, `field_type`, `connectivity`, `replacement_contract`, `rebuild`, `integrity`, `compiled_cache`, `save_version`, local `evidence`, and `patches`. Each patch has `fixture`, `start`, `end`, `before_hex`, `after_hex`; its before span must match a saved original heap body. All non-runtime requirements must then be resolved, with runtime still an owner check. Empty, unknown or placeholder recipe text is rejected.

A passing check establishes internal evidence consistency, not source authority, complete integrity rules, correct mathematical interpretation or LabVIEW validity. Fabricating semantically false but internally consistent claims is outside a syntactic verifier's power. The verifier includes negative self-checks for incomplete ready verdicts, unresolved requirements, missing local citations, hash corruption and wrong span bytes. It never requires `.session`, prepared sources, LabVIEW or an edited VI.
